2026-08-26, 22번 트리([[inas111_clma_2r3r30_tree_22]])에서 결함 excess 를 판정하려다
**같은 데이터에 네 번 다른 답을 냈다**:

| 시도 | V_In_1 결과 |
|---|---|
| host VBM/CBM 창에서 홀 계수 | −0.34 (무의미) |
| 자체 스펙트럼 갭 + `cum`(실제 전자수) | 후보 없음 |
| 자체 스펙트럼 갭 + `N* = 2m` | **−1** |
| + 충만/공백 조건 추가 | **금속성** |

그때마다 사용자에게 그 값을 근거로 물리적 해석까지 붙여 보고했다("±3 이 전부 ±1 로 나온다",
"셀 효과다", "완전 패시베이션이 갭을 좁혀 판정 불가"). **전부 판정자를 고칠 때마다 뒤집혔다.**

마지막에 같은 판정자를 **21번 트리(답을 아는 곳)** 에 돌려보니 21번 `pure`(분수점유 0 개로
닫힌껍질 확인됨)와 `V_In`(3.01 e = −3 으로 측정됨)까지 "금속성"으로 분류했다 →
**판정자가 틀렸다는 것이 그때서야 드러났다.** 그 대조를 처음에 했으면 세 턴을 아꼈다.

**Why**: 새 계에서 판정법을 만들면 정답을 모르므로 출력이 맞는지 알 수 없다. 그 상태로
해석을 붙이면 **판정자의 버그를 물리로 착각**하고, 사용자는 틀린 그림을 여러 턴 붙들게 된다.

**How to apply**:
1. 판정자를 새로 만들면 **반드시 답이 알려진 case 로 먼저 돌린다.** 이 프로젝트에는
   눈금자가 있다 — 21번 `pure`(excess 0) · `As_In`(0) · `V_In`(−3, 3.01 e) · `MA_i`(0),
   09번 `V_In`(−1, q−1 에서 부분점유 0).
2. 눈금자를 통과하지 못하면 **새 데이터에 적용하지 않는다.** 중간값을 보고하지도 않는다.
3. 판정법이 확정되기 전의 숫자는 "잠정"이라고 말하는 것으로 부족하다 —
   **아예 물리적 해석을 붙이지 않는다.** 해석은 사용자가 붙들게 되는 것이라 되돌리는 비용이 크다.
4. 방법을 바꿔야 하면 **바꾼 이유와 이전 값의 폐기를 먼저 밝히고** 새 값을 낸다.
