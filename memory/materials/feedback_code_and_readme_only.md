새 계산을 셋업할 때 **입력 생성기·실행 스크립트·수집 스크립트와 README까지만 만들고
멈춘다.** 실행은 사용자가 직접 한다.

**내가 하지 않는 것 (사용자가 명시적으로 시키기 전까지)**
- `sbatch` / `mpirun` / `nohup` 으로 계산 던지기
- 내가 만든 스크립트라도 **실행하기** — 수집·파싱 스크립트(`collect_*.py`) 포함
- `pkill` / `scancel` 등으로 **돌고 있는 계산 죽이기**. 죽이자는 제안도 하지 않는다
- 실행 중인 스크립트 파일 **편집** — bash가 바뀐 파일을 오프셋 기준으로 다시 읽어
  루프에 재진입하거나 즉사한다 ([[feedback_never_touch_running_calc]])

**Why:** 사용자가 입력을 눈으로 확인한 뒤 돌리고 싶어 한다. 계산 자원은 공유 자원이고,
발판(footing)이 한 번 어긋나면 그 뒤 스캔 전체가 오염된다. 2026-09-09에 두 번 지적받았다.

**How to apply:**
- 산출물 = ① 입력 생성기(단일 진실의 원천) ② 실행 스크립트(옵션은 env로 노출)
  ③ 결과 수집/판정 스크립트 ④ **README.md** — 폴더 트리, 각 폴더가 무슨 계산인지,
  계산 조건의 출처(논문/기존 트리), 실행법, 결과 읽는 법, 함정, 성공/실패 판정표.
- README 맨 앞에 "이 트리가 답할 질문"을 적는다.
- 마무리는 **실행 명령어를 적어 넘기는 것**까지. 그 다음은 사용자 차례.
- 읽기(cat/grep/ls, 로그 확인)는 해도 된다. 상태를 확인하고 보고하는 것은 무방하다.
