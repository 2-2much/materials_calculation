**계산 관련 파일은 사용자가 만들라고 한 것만 만든다.** 폴더·INCAR·KPOINTS·POSCAR·
run.sh·README 어느 것도 "도움이 될 것 같아서" 선제적으로 만들지 않는다.
설계는 **대화로 먼저 합의**하고, 만들라는 말을 들은 뒤에 만든다.
실행은 그 다음, 역시 사용자가 한다.

**내가 하지 않는 것 (사용자가 명시적으로 시키기 전까지)**
- **계산 입력/폴더를 먼저 만들어 놓기** — 2026-09-15에 지적받았다. "01-Train 폴더를
  만들고 싶다"는 **의도 표명**을 실행 지시로 읽고 트리 전체(INCAR·run.sh·모니터·README)를
  만들어버렸다. 사용자가 원한 건 **설계 논의**였다.
  질문으로 끝나는 문장(`~하는 것 어떤가?`)은 논의 요청이지 작업 지시가 아니다.
- `sbatch` / `mpirun` / `nohup` 으로 계산 던지기 — **DFT·AIMD·MLFF 학습/MD 전부 포함**
- 내가 만든 스크립트라도 **실행하기** — 수집·파싱 스크립트(`collect_*.py`) 포함
- `pkill` / `scancel` 등으로 **돌고 있는 계산 죽이기**. 죽이자는 제안도 하지 않는다
- 실행 중인 스크립트 파일 **편집** ([[feedback_never_touch_running_calc]])

**Why:** 사용자가 입력을 눈으로 확인한 뒤 돌리고 싶어 한다. 계산 자원은 공유 자원이고,
발판(footing)이 한 번 어긋나면 그 뒤 스캔 전체가 오염된다. 그리고 내가 만든 파일이
**엉뚱한 서버**에 생기면 순수한 쓰레기다 — `~/materials`의 `.gitignore`는 `*`라서
계산 파일이 서버 간에 동기화되지 않는다([[server_fs_git_sync_scope]]).

**How to apply:**
- 기본 산출물은 **텍스트 답변**이다. 표·설정값·실행 명령어를 대화에 적어서 넘긴다.
- 파일을 만들어도 되겠냐고 **한 줄로 묻고** 답을 기다린다.
- 만들라는 지시를 받은 뒤의 산출물 = ① 입력 생성기 ② 실행 스크립트(옵션은 env로 노출)
  ③ 결과 수집/판정 스크립트 ④ **README.md** — 폴더 트리, 각 폴더가 무슨 계산인지,
  계산 조건의 출처, 실행법, 결과 읽는 법, 함정, 성공/실패 판정표.
- README 맨 앞에 "이 트리가 답할 질문"을 적는다.
- **어느 서버에서 돌릴지 먼저 확인한다.** 세션이 붙어 있는 호스트 ≠ 사용자가 쓸 호스트.
- 읽기(cat/grep/ls, 로그 확인)는 해도 된다. 상태를 확인하고 보고하는 것은 무방하다.
- 조사용 서브에이전트를 띄울 때도 프롬프트에 **"읽기 전용, 계산 실행·제출·파일 생성 금지,
  임시 파일은 scratchpad에만"**을 명시한다.
